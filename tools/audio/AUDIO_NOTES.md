# 소리 굽기 메모 (tools/audio)

원본 「출근길 서바이벌」은 모든 소리를 브라우저에서 그 자리에서 합성한다(`commute-survival/js/audio.js`).
로블록스는 올린 소리 파일만 틀 수 있으므로, 원본 코드를 화면 없는 Chrome에서 그대로 돌려 WAV로 구웠다.

**아직 아무도 이 파일들을 귀로 들어 보지 않았다.** 아래의 검사는 모두 숫자와 그림(파형 · 스펙트로그램)으로 한 것이다.
로블록스에 올려 Studio에서 트는 것도 아직 해 보지 않았다(이 작업에서는 Studio를 쓰지 않았다).

## 명령

```
node tools/audio/bake.mjs        # 굽기 (약 3분). assets/audio/*.wav · src/shared/SoundMap.luau · SoundIds.luau · 이 문서의 표
node tools/audio/verify.mjs      # 구운 WAV를 다시 읽어 재기 + 그림(tools/audio/work/png/)
node tools/audio/test/run.mjs    # src/client/Sound.luau를 Studio 없이 돌려 보는 검사
```

- `bake.mjs`는 원본을 고치지 않는다. `tools/audio/work/audio.patched.js`에 복사본을 만들고 한 군데만 고친다:
  원본에 이미 있는 시험용 출구 `_test`에 안쪽 값 `I`(악기) · `HIT` · `VOICE` · `VOL` · `setPick`(원두 연속 횟수 지정)을 더 내놓는다. 소리를 만드는 코드는 한 글자도 바꾸지 않는다.
- `SoundIds.luau`에 이미 적어 둔 에셋 번호는 다시 구워도 지워지지 않는다.
- 난수는 씨앗을 고정했다 → 다시 구워도 같은 음 · 같은 무작위 갈래가 나온다. 다만 파일이 표본 하나까지 똑같지는 않을 수 있다
  (두 번 구워 견주면 음악에서 0.0000005쯤의 차이가 난다 — Chrome 안의 계산 순서 때문으로 보이며, 16비트 한 칸(0.00003)보다 작다).
- 굽는 데 쓰는 Chrome의 디버그 포트는 9351이다(달의 계승자의 34872 · 이 게임의 34880과 다르다). Chrome은 밖으로 아무것도 보내지 않게 띄운다.

## 올린 뒤에 할 일

1. `assets/audio/`의 WAV 4개(`sfx1.wav` · `music1.wav` · `music2.wav` · `music3.wav`)를 로블록스에 오디오로 올린다
   (크리에이터 허브 → Development Items → Audio, 또는 Studio의 Asset Manager).
   로블록스의 조건(공식 문서 create.roblox.com/docs/sound/assets, 2026-11-16에 읽음): `.mp3 · .ogg · .wav · .flac`, **20MB 미만 · 7분 이하 · 표본율 48kHz 이하**, 본인 인증 계정은 30일에 2,000개(미인증 100개). 네 파일 모두 이 조건 안이다(위 표).
   올린 뒤 심사를 통과해야 들린다.
2. 받은 번호를 `src/shared/SoundIds.luau`에 적는다. 키는 파일 이름과 같다:
   ```lua
   return {
       sfx1 = "rbxassetid://1234567890",   -- assets/audio/sfx1.wav
       music1 = "rbxassetid://…",          -- assets/audio/music1.wav
       music2 = "rbxassetid://…",
       music3 = "rbxassetid://…",
   }
   ```
   번호가 빈(`""`) 파일의 소리는 나지 않을 뿐 오류는 없다 → 하나씩 올려 가며 확인해도 된다.
3. 오디오는 올린 계정(또는 그룹)의 체험에서만 들린다. 「ssb」 체험(10777076565)의 주인과 다른 계정으로 올렸다면 그 오디오의 권한에서 이 체험을 허용해야 한다.
4. 게임 코드에서(화면 · UI 쪽 작업자가 연결):
   ```lua
   local Sound = require(script.Parent.Sound)      -- src/client/Sound.luau
   Sound.init()                                    -- 한 번 (여러 번 불러도 된다)
   Sound.vol(SET.music / 100, SET.sfx / 100)       -- 설정이 바뀔 때마다. 원본 기본값은 80 · 80
   -- Sim의 host.sfx(n, x, arg) → 원본처럼 플레이 중일 때만:
   Sound.sfx(n, pan, arg)                          -- pan은 받기만 하고 쓰지 않는다
   -- 프레임마다 (원본 main.js 246~247줄과 같은 값)
   Sound.music({ scene = ended and "off" or "play", station = S.song, boss = S.boss ~= nil, muffled = not running,
                 late = S.rage > 0, lowhp = S.p.hp / S.p.maxhp < 0.3, crowd = #S.enemies })
   Sound.music({ scene = "menu" })                 -- 메뉴 화면에서
   ```
5. **Studio에서 꼭 귀로 확인할 것** (여기서는 확인하지 못했다):
   - 구간 재생(`PlaybackRegionsEnabled` · `PlaybackRegion`)이 긴 파일에서도 바로, 정확한 자리에서 시작하는가. 앞 소리의 꼬리나 다음 소리의 머리가 섞여 들리지 않는가(구간 사이에 0.25초의 무음을 두었다).
   - 음악의 되풀이(`LoopRegion`)가 끊김 없이 이어지는가. 파일 안에서는 표본 단위로 이어지게 만들었지만, 로블록스가 올린 파일을 다시 압축하거나 경계를 한두 표본 다르게 잡으면 작은 틱 소리가 날 수 있다.
   - 보스 층(킥 · 드론 · 경보)이 노래의 박자와 맞는가. 두 `Sound`를 `TimePosition`으로 맞추는데, 그 정밀도는 문서에 없다. 어긋나면 `Sound.luau`의 `STEM_RESYNC` · `STEM_SLACK`을 만져 본다.
   - 멈춤 화면의 먹먹함(`EqualizerSoundEffect` 중음 -16dB · 고음 -48dB)이 원본(520Hz 저역 통과)과 비슷하게 들리는가. 값은 `bake.mjs`가 `SoundMap.music.muffle`에 적는다.
   - 전체 크기. `Sound.luau`의 `MASTER = 0.7`로 조금 낮춰 두었다(아래 「원본과 다른 점」 2).

## 음악을 어떻게 옮겼나

원본 `music(state)`는 16분음표(스텝)마다 악기를 부르는 시퀀서다. 읽어서 확인한 구조:

- 메뉴 노래 1곡(92bpm) + 역마다 1곡씩 5곡(신도림 112 · 사당 120 · 교대 126 · 강남 132 · 역삼 140bpm). `state.station`(= Sim의 `S.song`, 0~4)이 곡을 고른다.
- 역 노래는 64스텝(4마디)을 한 「악구」로 하여 악기가 차례로 더해진다: 악구 0 = 드럼 · 베이스 · 패드, 1부터 멜로디, 2부터 아르페지오, 3부터 멜로디 한 옥타브 위, 4부터 아르페지오가 한 옥타브 위. 악구 4부터는 2악구(128스텝)마다 똑같이 되풀이된다(홀수 악구에서 스네어 대신 박수가 들어가서 주기가 2악구).
  → **도입부(악구 0~3) + 되풀이(2악구)** 로 구웠다. `PlaybackRegion`으로 처음부터 틀고 `LoopRegion`으로 뒤 2악구만 되풀이한다. 원본도 곡이 바뀌면 스텝 0부터 다시 시작하므로 흐름이 같다.
- 메뉴 노래는 처음부터 64스텝 주기다 → 도입(첫 바퀴, 앞 꼬리 없이 깨끗하게 시작) + 되풀이(둘째 바퀴).
- `boss`: 원본은 같은 곡 위에 킥(2 · 10번째 스텝) · 낮은 드론 · 두 음 경보를 더한다 → **보스 층**으로 따로 구웠다(곡마다 64스텝 순환, 모노, `sfx1.wav` 맨 앞). 보스가 나오면 노래의 스텝 위치에 맞춰 겹쳐 틀고 0.25초에 걸쳐 올린다.
  굽는 법: 원본 `playStep`을 `boss` 없이/있이 두 번 소리 없이 돌려 악기 호출을 견주고, 보스일 때만 더해지는 호출만 실제로 울렸다(원본 코드를 따라 쓰지 않았다).
- `late`(지각): 원본은 박자가 8% 빨라지고 스네어가 더 들어간다 → `PlaybackSpeed = 1.08`.
- `muffled`(멈춤 · 레벨 업 화면): 원본은 음악에만 520Hz 저역 통과 → 음악 묶음에 `EqualizerSoundEffect`.
- `lowhp`: 0.78초마다 심장 박동 두 번 → 구운 `_heart` 구간을 0.78초마다.
- `crowd`: 적 수에 따라 웅성거림(갈색 잡음)의 크기가 `min(0.05, 적 수/8000)` → 최대 크기(적 400마리)로 구운 6초 순환을 `min(1, 적 수/400)`의 음량으로.
- 곡이 바뀔 때(처음이 아니고 메뉴 곡이 아닐 때) 심벌 한 번 → 구운 `_crash` 구간.
- 음악 음량이 0이면 곡을 멈추고, 다시 켜면 처음부터(원본과 같다).

파일 나누기: 스테레오 WAV는 1분에 10.6MB라 20MB 한도 때문에 곡을 둘씩 묶었다 — `music1` = 역 0 · 1, `music2` = 역 2 · 3, `music3` = 역 4 · 메뉴. 효과음과 모노 순환(보스 층 · 웅성거림)은 `sfx1` 하나.

## 원본과 다른 점

1. **좌우 치우침(pan)이 없다.** 원본은 적의 위치에 따라 효과음을 좌우로 보낸다. 로블록스의 2D `Sound`에는 그 기능이 없어 가운데서만 난다. 효과음 파일도 모노로 구웠다(잔향의 좌우 퍼짐만 사라진다 — 좌우 차이의 에너지는 가장 큰 것(`evo`)이 가운데의 3.2%, 그다음(`win`)이 1.1%, 절반 넘는 구간은 0%).
2. **컴프레서 · 리미터를 함께 지나지 않는다.** 원본은 음악과 모든 효과음을 한 컴프레서 → 리미터에 넣는다(큰 소리가 겹치면 서로 눌린다). 구울 때는 소리 하나하나를 따로 그 체인에 통과시켰다 → 하나씩의 음색 · 크기는 원본과 같지만, 겹칠 때 서로 누르는 효과는 없고 그냥 더해진다. 넘치지 않게 `Sound.luau`에서 전체를 0.7배로 낮췄다(음악 최대 0.72 = -2.8dBFS, 효과음 최대 0.76 = -2.4dBFS). 들어 보고 원본의 「서로 눌리는」 느낌이 필요하면 두 묶음 위에 `CompressorSoundEffect`를 얹는 길이 있다(해 보지 않았다).
3. **무작위가 몇 가지로 줄었다.** 원본은 타격음 · 처치음 · 보스 목소리 등의 높이를 부를 때마다 무작위로 정한다 → 3가지(kill은 4가지)를 구워 돌려 쓴다(같은 것이 잇달아 나오지 않게). 잡음의 결도 원본은 매번 다르지만 구운 것은 늘 같다.
4. **음악의 미세한 차이가 없다.** 원본은 같은 악구라도 음마다 아주 조금씩 다르게 난다(잡음, 음이 시작하는 표본 위치). 구운 순환은 2악구마다 완전히 같다. 박자도 순환 길이를 128표본의 배수로 맞추느라 0.02%쯤 달라졌다(112 → 112.005 · 120 → 120.011 · 126 그대로 · 132 → 131.983 · 140 → 139.970 · 메뉴 92 → 92.003bpm). 도입부에서 되풀이로 처음 넘어가는 한 곳은 원래 흐름과 최대 0.027(-31dBFS)만큼 달라서 30ms에 걸쳐 섞어 이었다(되풀이 자체의 이음매는 차이 0.0000005 이하).
5. **보스 층은 되풀이 구간 기준이다.** 원본은 보스가 곡의 처음 4악구(27~34초) 안에 나오면 아르페지오와 옥타브 멜로디도 미리 켠다 — 구운 보스 층에는 킥 · 드론 · 경보만 있다. 또 보스 층도 따로 구웠으므로 2번과 같은 차이가 있다.
6. **지각(`late`)**: `PlaybackSpeed`를 올리면 박자와 함께 음높이도 8%(약 1.3반음) 오른다. 원본은 음높이는 그대로이고 스네어가 더 들어간다(그 스네어는 없다).
7. **먹먹함**은 3대역 이퀄라이저로 흉내 낸 것이라 원본의 저역 통과와 기울기가 다르다.
8. **곡이 바뀔 때** 원본은 앞 곡의 울리던 음이 저절로 사라지고, 여기서는 앞 곡을 0.35초에 걸쳐 내린다. 게임이 끝났을 때(`scene = "off"`)도 같다.
9. **꼬리 자르기**: 효과음마다 소리가 -60dBFS(작은 소리는 최대값의 1/100) 아래로 내려간 곳에서 자르고 30ms에 걸쳐 0으로 내렸다. 잔향의 아주 끝이 그만큼 짧다.
10. **동시에 나는 수**: 원본은 제한이 없고, 여기는 24개(모자라면 가장 먼저 끝날 소리를 끊고 쓴다). 일부러 심하게 만든 전투 검사(10초 동안 프레임마다 무기 6종의 타격 · 처치 · 원두 · 치명타를 모두 부름 → 초당 185번 소리)에서 24개가 다 찼고 1,850번 가운데 49번은 울리던 소리를 끊었다.
11. **시계**: 원본의 최소 간격은 오디오 시계로, 여기는 `os.clock()`으로 잰다(결과는 같다).

## 굽는 방법에서 알아 둘 것

- 모든 소리는 원본과 같은 연결(효과음 게인 1.5 · 음악 게인 0.45 → master 0.72 → 컴프레서 → 리미터 → 0.84)을 지나 나온 최종 출력이다(음량 설정 100% 기준 — 설정값은 `Sound.vol`이 곱한다). Chrome의 컴프레서는 스스로 음량을 올려 주기 때문에(make-up gain) 게인만 곱해 계산한 것보다 크다 — 킥 하나만 울려도 최대값이 0.62, 음악 전체는 0.72다. 원본을 브라우저에서 틀 때도 같다.
- Chrome은 소리를 128표본씩 만든다. 되풀이 길이가 128의 배수가 아니던 곡(112 · 120 · 132bpm · 메뉴)은 「한 바퀴 뒤의 같은 자리」가 전혀 다른 파형이었다(차이 0.63~0.96). 악기를 하나씩만 울려 보니 오실레이터를 쓰는 악기(킥 · 스네어 · 베이스 · 멜로디 · 아르페지오 · 패드)만 그랬고 잡음만 쓰는 악기(하이햇 · 박수 · 심벌)는 같았다 — 음이 128표본 단위 안의 어디에서 시작하느냐에 따라 결과가 달라지는 것으로 보인다(까닭은 더 파지 않았다). 길이를 128의 배수로 맞추자 차이가 0.0000005 아래로 내려갔다.
- 효과음은 원본처럼 렌더 단위의 경계(`currentTime`)에서 낸다. 음악의 스텝은 원본처럼 `60/bpm/4`초씩 가면서 표본 사이에 놓이는 자리(소수)를 그대로 따른다 — 잡음 악기(하이햇 등)는 그 자리에 따라 밝기가 달라지기 때문이다.
- 한꺼번에 수만 개의 음을 예약하면 렌더가 몹시 느려진다 → 원본처럼 1초씩 앞서 예약한다(`OfflineAudioContext.suspend`).
- 순환 이음매: 순환 구간의 첫 30ms는 「끝에서 자연스럽게 이어지는 소리」에서 시작해 제자리로 옮겨 타게 섞었다(두 소리가 같으므로 사실상 아무것도 바뀌지 않는다). 도입부의 끝 30ms도 순환 구간 직전의 흐름으로 옮겨 탄다. 순환 구간의 앞뒤에는 이어지는 소리 64표본을 덧붙여 두었다(로블록스가 경계를 한두 표본 다르게 잡을 때를 위해).
- 구간의 시각은 100만분의 1초까지 적었다(표본 하나는 0.0000227초). 로블록스의 `NumberRange`가 32비트 실수라면(확인하지 못했다) 100초 근처의 시각은 약 0.3표본까지만 정확하다 — 그래서 `sfx1`에서는 순환하는 것(보스 층 · 웅성거림)을 파일의 맨 앞에 두었다.
