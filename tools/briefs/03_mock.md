# Task: a headless harness that runs Roblox GUI game code without Studio (and takes approximate screenshots)

Read `c:\YJS\Roblox\ssb\tools\briefs\00_common.md` first and obey it.

## Why
We are porting a browser game to Roblox as a pure-GUI 2D game (ScreenGui + Frames/ImageLabels/TextLabels; the whole simulation runs on the client; the server only saves records). We cannot use Studio in this session, so this harness is our only way to execute the client code, catch runtime errors and API misuse, and see roughly what the screen looks like.

The game code does not exist yet — others are writing `src\shared\Sim.luau` (pure Luau rules) and `src\shared\art\*` (atlas manifest `Atlas.luau`, pixel modules, `Decode.luau`; atlas PNGs land in `c:\YJS\Roblox\ssb\assets\`) right now; the client (`src\client\*.luau`, entry `*.client.luau`) and server (`src\server\*.server.luau`) come after you. So build and test the harness against sample scripts of your own (under `tools\mock\sample\`, with their own small project json), and make it work on whatever is in `src\` through `c:\YJS\Roblox\ssb\default.project.json` (Rojo project: `src/shared` → ReplicatedStorage.shared, `src/server` → ServerScriptService.server, `src/client` → StarterPlayer.StarterPlayerScripts.client; Rojo naming: `x.luau` = ModuleScript, `x.client.luau` = LocalScript, `x.server.luau` = Script, `init.luau`/`init.client.luau`/`init.server.luau` turn the folder into that script, plain folders = Folder).

Because the Luau CLI cannot read files, a node script must bundle all project sources into one generated Luau file (each module as a function in a table keyed by its instance path) and run luau.exe on it; data comes back through stdout.

You may download public reference data: the Roblox API dump (`https://raw.githubusercontent.com/MaximumADHD/Roblox-Client-Tracker/roblox/API-Dump.json`) and luau-lsp's Roblox type definitions (`https://raw.githubusercontent.com/JohnnyMorganz/luau-lsp/main/scripts/globalTypes.d.luau`). For a realistic picture of the API surface our client will use, you may READ (never write) these files of the other game: `C:\YJS\Roblox\sprite-gen\SpriteDemo\src\client\lune\stage.luau`, `canvas.luau`, `sprite.luau`.

## Deliverables (all under `c:\YJS\Roblox\ssb\tools\mock\`)
1. `bundle.mjs` — builds the virtual DataModel from a Rojo project json and emits the bundle.
2. The mock runtime (Luau):
   - Instances with real class names, validated against the API dump: creating an unknown class, reading/writing an unknown property, assigning a wrong type (number to a UDim2 property, string to an Enum property, wrong Enum type, …), calling an unknown method, or using an unknown Enum item must raise an error with a useful message and traceback — catching typos is the main point. Support `Instance.new(class, parent?)`, Parent/Name/children APIs (`FindFirstChild`, `WaitForChild`, `GetChildren`, `GetDescendants`, `FindFirstChildOfClass`, `FindFirstChildWhichIsA`, `FindFirstAncestor…`, `IsA`, `IsDescendantOf`, `Clone`, `Destroy`, `ClearAllChildren`), attributes, `GetPropertyChangedSignal`, `Changed`, `ChildAdded/Removed`, `AncestryChanged`, `Destroying`, signals with `Connect/Once/Wait/Disconnect`.
   - Datatypes with arithmetic/methods as in Roblox: Vector2, Vector3 (basic), UDim, UDim2 (`new/fromScale/fromOffset`, `Lerp`), Color3 (`new/fromRGB/fromHSV/fromHex`, `Lerp`, `ToHSV`, `ToHex`), Rect, NumberRange, NumberSequence, ColorSequence (+Keypoints), TweenInfo, Font (`new/fromEnum/fromName/fromId`), Content (`fromUri/fromObject/none`), `Enum.*`, `typeof` returning Roblox type names, `tick`, `time`, `os.clock`/`os.time` on a virtual clock, `warn`, `task.spawn/defer/delay/wait/cancel` and legacy `wait/delay/spawn` on a deterministic scheduler driven by the harness.
   - Services through `game:GetService` and `game.X`: Players (`LocalPlayer` with `UserId`, `Name`, `PlayerGui`; `PlayerAdded/PlayerRemoving`, `GetPlayers`, `CharacterAutoLoads`), RunService (`RenderStepped`, `Heartbeat`, `PreRender`, `PreSimulation`, `PostSimulation`, `BindToRenderStep`, `IsClient/IsServer/IsStudio`), UserInputService (`InputBegan/InputChanged/InputEnded`, `TouchStarted/Moved/Ended`, `IsKeyDown`, `GetMouseLocation`, `TouchEnabled/KeyboardEnabled/MouseEnabled/GamepadEnabled`, `PreferredInput`, `GetFocusedTextBox`, `TextBoxFocusReleased`, `WindowFocused/WindowFocusReleased`), ContextActionService (basic), GuiService (`GetGuiInset`, `TouchControlsEnabled`, `MenuOpened/MenuClosed`), StarterGui (`SetCoreGuiEnabled`, `SetCore`), TweenService (`Create` → tween advancing with virtual time, `Play/Cancel/Pause`, `Completed`; easing may be approximate but must reach the end value), ReplicatedStorage/ReplicatedFirst/ServerScriptService/ServerStorage/Workspace (`CurrentCamera.ViewportSize`), AssetService (`CreateEditableImage({Size=…})` → mock EditableImage with `Size`, `WritePixelsBuffer(pos,size,buffer)` validating the buffer length, `ReadPixelsBuffer`, `Destroy`), ContentProvider (`PreloadAsync` no-op), SoundService + `Sound` instances (`Play/Stop/Pause/Resume`, `Ended`), DataStoreService (in-memory `GetDataStore`, `GetAsync/SetAsync/UpdateAsync/RemoveAsync`, optionally injected failures), HttpService (`JSONEncode/JSONDecode/GenerateGUID`), TextService (`GetTextSize` approximate; Hangul/CJK glyphs ≈ 1em wide, Latin ≈ 0.5em), MarketplaceService/Teams/Lighting/TextChatService as inert stubs, `game:BindToClose`, `game.PlaceId/GameId/JobId`.
   - Client and server in one VM: Scripts under ServerScriptService run in a "server" context, LocalScripts under StarterPlayerScripts (cloned into the fake player's PlayerScripts) in a "client" context; `RemoteEvent` (`FireServer/OnServerEvent`, `FireClient/FireAllClients/OnClientEvent`), `UnreliableRemoteEvent`, `RemoteFunction` (`InvokeServer/OnServerInvoke`, …), `BindableEvent/Function` deliver across contexts through the scheduler. `require(moduleScriptInstance)` with per-context module caching and the correct `script` global; also require-by-string (`require("./Sibling")`, `require("@self/Child")`) resolved against the instance tree.
   - GUI layout: `AbsolutePosition`, `AbsoluteSize`, `AbsoluteRotation` for GuiObjects under a ScreenGui in PlayerGui from Position/Size/AnchorPoint/parents, `UIScale` (nested), `UIPadding`, `UIAspectRatioConstraint`, `UISizeConstraint`, `UIListLayout`/`UIGridLayout` (reasonable basics: Padding, FillDirection, alignment, SortOrder/LayoutOrder, `AbsoluteContentSize`), `AutomaticSize` (approximate from children/text), `TextBounds`/`TextFits` (approximate), `IgnoreGuiInset`, `ScrollingFrame.CanvasSize/CanvasPosition`, `ClipsDescendants`, `Visible`, ZIndex with `ZIndexBehavior.Sibling`, `DisplayOrder`. Configurable viewport (default 1280×720; also test 844×390 phone landscape). Layout is recomputed lazily and fires `AbsoluteSize`/`AbsolutePosition` changed signals.

3. `run.mjs` — the driver: `node tools/mock/run.mjs [--project default.project.json] [--viewport 1280x720] [--frames N] [--script path\to\scenario.luau] [--shot out.png …]`. A scenario is a Luau file receiving a `harness` object (step frames with a dt, advance time, simulate input, find instances by path/name/text, read properties, assert, request screenshots, print). Without a scenario: start server scripts, then client scripts, step N frames at 60 fps, report every error (traceback mapped back to source file + line) and every `warn`. Non-zero exit code on errors.
4. Screenshots: dump the visible GUI tree (absolute rects, clipping, ZIndex order, colours/transparencies, UICorner, UIStroke, UIGradient (approximate), Rotation, text + font size + alignment + colour + stroke, images with `ImageRectOffset/ImageRectSize` incl. negative width = horizontal flip, `ImageColor3`, `ImageTransparency`, `ScaleType` Stretch/Fit/Crop/Tile/Slice (basic), `ResampleMode`) to JSON; a node script turns it into an HTML page and headless Chrome (`--headless=new --screenshot=<png> --window-size=W,H`) renders a PNG. Image sources: `rbxassetid://…`/`rbxasset://…` → a labelled placeholder unless a mapping file names a local PNG; `Content.fromObject(EditableImage)` → the pixels actually written into that mock EditableImage. Korean text must render (system Korean font such as Malgun Gothic). It will not be pixel-identical to Roblox — approximate but honest; note known differences.
5. Static checking: `node tools/mock/analyze.mjs` runs `luau-analyze` over `src\` with the Roblox definitions file (find the flags this build supports; resolve `require(script.Parent.X)` as best you can, e.g. a generated sourcemap/.luaurc aliases, or accept `any`), printing a deduplicated error list filtered so that unresolvable-require noise does not drown real problems.
6. `tools\mock\README.md` (Korean): how to run, how to write a scenario, what is validated, and an explicit list of what the mock does NOT model or only approximates (so nobody mistakes a green run for "works in Roblox").
